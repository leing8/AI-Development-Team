# 编制

用户只对接接口人。接口人指定一个主人，主人按技能工作。Subagent 不直接跟用户聊天。

## 主人

- 产品：新功能、范围、优先级、验收标准。规则冲突时说明旧行为是保留还是废弃。
- 技术负责人：规则的家、影响清单、设计、风险。派工前先做影响分析。
- 接口人：缺陷、小改动、进度、复盘。碰已登记规则时仍然要有影响清单。

## Subagent

- `planner`：只读拆任务。不能把「再写一个方法」拆成任务，除非影响清单里有用户确认过的例外。
- `implementer`：只改清单里的那个实现。发现清单外的相似代码就停手。
- `test-engineer`：先锁住未废弃的旧行为，再覆盖新行为。
- `security-auditor`：只读。查注入、越权、密钥和敏感数据。
- `verifier`：只读。漏改、第二份实现、被改含义的旧测试，都判不通过。

## 档案

模板在 `.team/templates/`。一次需求一个目录 `.team/engagements/<id>/`，`<id>` 用简短英文短横线。

| 文件 | 谁写入 | 作用 |
| --- | --- | --- |
| `status.md` | 接口人 | `状态: 进行中` 或 `状态: 已关闭` |
| `intake.md` | 接口人 | 已知信息和未解决的问题 |
| `prd.md` | 产品 | 成功标准、非目标、与旧行为的关系 |
| `impact.md` | 技术负责人 | 搜过哪里、规则的家、必须一起改的位置 |
| `design.md` | 技术负责人 | 复用、扩展或例外，以及风险和回滚 |
| `adr.md` | 技术负责人 | 难以逆转的选择 |
| `tasks.md` | 接口人 | `planner` 交回的任务 |
| `review.md` | 接口人 | 评审结论 |
| `verification.md` | 接口人 | `结论: 通过` 或 `结论: 不通过` |
| `handoff.md` | 接口人 | 交给用户的证据和回滚方式 |
| `retro.md` | 接口人 | 哪条规则差点被写成第二份 |

父 Agent 写这些档案。只读 Subagent 只交回结论。

## 钩子

- 会话开始时提醒未关闭的需求，并要求先读本登记册。
- 每次改文件会记下路径。回合结束时，如果改了代码却没有 `verification.md`，会要求派出 `verifier`。只提醒一次。
- `git push --force` 和 `git reset --hard` 需要确认。`--force-with-lease` 不拦截。

钩子状态在 `.cursor/hooks/state/`，不提交。

## 外接

不在仓库里保存密钥。需要 GitHub 或文档查询时，在 Cursor 里单独配置 MCP。本团队不内置会联网的服务。
