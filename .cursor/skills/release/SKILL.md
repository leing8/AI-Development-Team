# 发布检查

在 `verification.md` 的结论为通过之后进行。缺一项就不宣布可交付。

## 清单

- 成功标准有对应的测试或手动验证证据。
- 影响清单中的位置都已处理。
- `.team/capabilities.md` 已写入本次形成或改变的规则；没有新规则则写明未改变登记册及原因。
- 风险和回滚方式写在 `design.md` 或 `handoff.md`。
- 密钥和令牌没有进入代码、日志或档案。
- 范围没有超出 `prd.md` 的非目标。

## 输出

写入 `.team/engagements/<id>/handoff.md`。接口人用它向用户报告：改了哪些已有入口、证据是什么、如何回滚。

证据不足时回到 `verifier`，不要补一句「应该可以」。
