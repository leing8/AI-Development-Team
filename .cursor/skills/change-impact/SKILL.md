# 影响分析

在派 `planner` 和 `implementer` 之前做完。结果写入 `.team/engagements/<id>/impact.md`。

## 搜索顺序

1. `.team/capabilities.md` 里语义相近的规则。
2. 登记的代码位置及其调用处。
3. 仓库里相近的符号、文件名、配置键、文案和测试名。
4. 其他 `.team/engagements/*/prd.md` 与 `design.md` 里描述同一行为的记录。

搜索范围写进清单。没搜到要写「搜过哪里、没有命中」，不能只写「没有旧实现」。

## 清单必须回答

- 这条规则现在的家在哪个路径和符号。没有则写「尚无」。
- 必须一起改的入口、调用点、配置、文案、测试。
- 确认不动的位置，以及为什么不动。
- 与旧规则是并存、扩展还是替代。含义冲突且没有用户裁决时，停。
- 决定：复用、扩展，或例外。例外要有原因和淘汰期限。

## 停手

- 清单外又发现相似实现。
- 多个入口只准备改其中一个，且没有说明其余入口为什么不动。
- 配置和代码各写一份同一规则。

把停手原因交回接口人，不要继续派实现。
