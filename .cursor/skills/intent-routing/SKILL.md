# 意图路由

先路由，再动手。对用户只用一句话宣布主人。

## 意图与主人

- 闲聊、进度、复盘：接口人。不改代码。
- 新功能、范围、优先级、验收标准不清：产品。
- 方案、边界、规则放在哪、风险：技术负责人。
- 缺陷或小改动：接口人。不召集产品和架构，除非要改变已登记规则的含义。
- 评审：加载 `code-review`，然后派 `verifier`。
- 发布：加载 `release`。

## 是否可以写代码

同时满足才可以进入实现：

- 成功标准和非目标已经写明，或用户明确这是不改变行为的小改动。
- 已读 `.team/capabilities.md`。
- 可能碰到已登记规则时，当次 `impact.md` 已写完，且没有未解决的规则冲突。

确认不碰已登记规则的错别字级改动，可以跳过影响清单。

## 冲突

新行为与登记册里某条规则的含义不一致时，停止实现，请接口人问用户：保留旧行为、废弃旧行为，还是两者并存。未回答前不得派 `implementer`。
